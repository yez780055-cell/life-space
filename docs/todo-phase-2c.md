## 已交付的本机功能

- 情侣事项与个人待办使用不同的 IndexedDB stores；Phase 2C 的版本升级只新增 `coupleItems` 和 `coupleTags`，不转换或删除既有个人任务、标签和周期记录。
- 情侣事项支持快速或详细新增、编辑标题/日期/时间/标签/备注、确认删除、完成、短时撤销、历史恢复，以及设备本机持久化。详细新增可一次保存日期、时间、标签和备注；快速新增支持连续录入。
- 首页按是否有安排日期分为两列。桌面端可从卡片主体拖动；手机端长按卡片主体后拖动。拖到“已安排”会安排到本机今天，拖到“未安排”会清空日期和时间；具体日期与时间可在编辑页调整。
- 标签名称规范化后复用；多个选中标签按 OR 规则筛选首页和历史。
- 完成时间使用时间戳保存，历史按本机日历时区显示，支持 7、30、90、180、365 天和含首尾日期的自定义范围。
- 页面明确提示数据仅在此设备保存。不同浏览器或设备之间目前没有共享。

## 本机数据与并发约束

`src/modules/todo/couple/model.ts` 定义与存储实现无关的记录形状，`CoupleTodoRepository` 是后续适配器接口；当前 `useCoupleTodo` 默认使用 IndexedDB `coupleRepository`。每条记录保留稳定 ID、创建/更新时间和单调递增 `revision`。编辑、完成、撤销和删除均可携带期望 revision；旧 revision 会被拒绝，避免静默覆盖另一处更新。

标签存储独立于个人标签。删除仍有关联事项的标签会被拒绝。数据库 v3 到 v4 的升级是新增 store/index，不重写用户记录。

## 跨设备共享准备（尚未启用）

`supabase/migrations/202610160001_couple_todo.sql` 描述未来的远程表、RLS 和 RPC：

- 每个账号最多加入一个共享空间，每个空间最多两名成员；加入通过一次性邀请完成。
- 邀请随机令牌只在创建时返回，数据库仅存 SHA-256 摘要；令牌 30 分钟过期，生成新邀请会撤销前一张未使用邀请。
- 数据表默认拒绝匿名访问；远程数据通过成员 RLS 检查。客户端不能直接改写事项行，事项变更要通过带 `expected_revision` 的 RPC；删除采用 tombstone，便于未来同步时传播删除状态。
- 日期和时间作为本地日历日期及无时区墙上时间保存。后续 UI 必须明确双方采用的日历时区，不能将 `HH:mm` 当作 UTC 时间转换。

此迁移文件没有应用到任何 Supabase 项目。应用没有 Supabase SDK、项目 URL、密钥、登录/配对界面，也没有远程 repository 实现；因此当前不得声称账号、配对或同步已完成。未来接通前需要单独配置 Auth、应用 URL 与公开 anon/publishable key，应用 RLS 迁移，再实现 RPC repository、邀请界面、用户主动选择的本机数据导入和冲突处理。服务端 `service_role` 密钥不能放进客户端。
