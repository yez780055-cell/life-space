# Todo Phase 2B：个人数据与暂行规则

## 数据与日历模型

IndexedDB 从 v2 升至 v3，新建 `todoTasks`、`todoTags`、`todoOccurrences` 三个 object stores；原有设置与模块命名空间保留。任务本体只保存一次，重复任务通过本地日历规则按当前查看区间生成实例，实例完成状态、子任务勾选、单次修改和跳过状态放在 `todoOccurrences`。数据库不预先复制未来任务。

日期键使用设备本地 `YYYY-MM-DD`，不经 UTC 日期截断。周视图以周一至周日排列。按系列编辑时，新规则从所选周期起生效；旧规则结束于此前一天，旧周期记录保留。将重复频率改为“不重复”时，所选任务保留为一次性待办，之后周期停止；把一次性任务再次设为重复会从所选开始日期生成新规则。

月历焦点直接展开在所选日期格。该日期格占用四列和多行，周围日期在原网格中让位；完整任务在格内滚动，任务完成、编辑和按日期快速新增复用个人任务存储。焦点状态属于 Todo 子页面，可由浏览器返回收起。减少动态效果时取消放大动画，但仍保留同一网格展开布局。

## 子任务与周期暂行规则

- 当前及未来的日、周、月实例只按其实际周期显示；未完成的旧周期不自动搬到今天。
- 每月按开始日期的日号重复；该月没有该日时跳过，不自动移到月底。
- 所有非空子任务勾选后，父任务自动完成。若父任务是因子任务完成而完成，后来取消任一勾选会撤销自动完成；用户手动完成的父任务不会因取消子任务勾选而撤销。
- 重复任务的子任务勾选与完成时间按周期分别保存。仅此周期的标题、日期、时间、标签、备注、子任务和提醒存为实例覆盖。
- 本机时区用于日期和提醒计算。将“每周”配置为多个星期时按所选星期生成；未配置星期会默认使用开始日期的星期。

这些规则是 Phase 2B 的可逆实现选择，后续如产品确认不同语义，可调整数据层并迁移，不视为最终产品定义。

## 标签与提醒

个人标签可创建、复用、多选和保存到任务；名称会去除首尾空格、折叠连续空格，并按不区分大小写的规范化名称去重。此阶段没有个人任务的标签筛选，也没有标签重命名、批量删除或删除关联数据的管理界面。情侣标签仍使用独立演示内容。

提醒设置保存在任务/周期覆盖中，用户点击后才请求通知权限。当前只支持单个提前提醒，选项为准时、5、10、30 分钟或 1 小时；新建任务暂用提前 10 分钟作为初始值。获得权限后，网页打开期间使用前台定时器并通过 Service Worker 或浏览器通知尝试投递；页面关闭后不保证提醒。错过的提醒不会在重开时补发。该能力不等于 Android 原生后台通知。

## 待产品确认

以下选择目前没有作为最终产品要求定稿：

1. 提醒默认提前多久、是否允许多个提醒，以及重复任务是否可为每个周期设不同提醒。
2. 每月 29、30、31 日在较短月份的处理方式：跳过、月底执行或其他规则。
3. 重复规则变更的产品文案与范围。当前 UI 采用“仅此周期”或“此周期及之后”，旧周期按实际完成记录保留。
4. 个人标签的重命名、删除、关联任务处理与筛选规则。
5. 更换设备后的备份、迁移与同步策略。

## 不在 Phase 2B

情侣事项真实 CRUD、拖拽安排、标签筛选、真实完成历史，账号/云同步，以及可靠的网页关闭后提醒和 Android 原生通知均未实现。情侣区域、历史筛选与情侣编辑仍明确标识为 UI 演示。
